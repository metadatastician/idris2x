= Threat Model
:toc: macro

== Threat Model: idris2x

=== Document Info

Version 0.1 (Phase 0, 2026-11-09). Sources: the plan's Section 4, the Phase 0 red-team audit (primary sources cited inline), and the prototype drills in `scripts/proto/chaos.sh`.

toc::[]

=== Scope

==== In Scope
* The launcher binary, its cache/store, the lockfile, the signed channel manifest, capsule archives, mirrors, the factory CI, the maintainer's keys, the first-install (bootstrap) path, the air-gap path.

==== Out of Scope
* Bugs inside Idris 2 or Chez Scheme themselves (zero-fork policy: reported upstream, see `docs/status/UPSTREAM-NOTES.adoc`).
* Compromise of the user's own machine or account.

=== System Overview

`idris2x.toml` → `idris2x.lock` (digests + URLs) → launcher: resolve (local) → fetch (any mirror) → verify (sha256, tar rules) → unpack to staging → probes → atomic rename → `.complete` → direct `execve` of the capsule's Chez with an explicit environment. Resolution (`pin`/`update`) additionally fetches the channel manifest and verifies its Ed25519 signature, monotonic `channel_version` and `expires`. Execution never needs the manifest.

=== Assets

. Integrity of what executes (the pinned digest, nothing else) — I1/I5.
. The channel signing key(s); the embedded root public key.
. Availability of capsules for existing locks after abandonment — I4.
. The maintainer's and users' privacy (no telemetry).
. Redistribution compliance (Apache-2.0 + NOTICE, BSD-3, LZ4 BSD-2, Nanopass MIT, zlib).

=== Trust Boundaries

[cols="1,2,2",options="header"]
|===
| Boundary | Trusted side | Untrusted side
| Channel signature | Embedded root public key, manifest bytes that verify | Every mirror, every URL, GitHub, Cloudflare, the network
| Lockfile | The project's reviewed `idris2x.lock` | Anything not matching its sha256
| Store | Directories with `.complete` whose `sha256sums.txt` verifies | Staging dirs, partial downloads, dirs without the marker
| Process environment | Variables the launcher sets | Inherited `IDRIS2_*`, `LD_LIBRARY_PATH`, `DYLD_*`, `CHEZ`, `PATH`
| Capsule archive | Members that pass the extractor rules | Absolute paths, `..`, escaping links, hardlinks, devices, setuid bits
|===

=== Threat Actors

Malicious or compromised mirror; compromised CI runner or GitHub token; network attacker (TLS stripping is out of scope for HTTPS-only URLs, but a captive portal can serve 200s); a squatter who registers the repository name after a rename or deletion; a local unprivileged process sharing the cache (CI runners); the maintainer's own mistakes.

=== STRIDE Analysis

==== Spoofing
* *Fake manifest / fake mirror.* Mitigated: Ed25519 signature with the key pinned in the launcher; key-id must match; pre-hashed formats rejected (`E-SIG-INVALID`). Drilled: tampered manifest, wrong key.
* *Repository squatting after rename/transfer.* GitHub keeps a 301 from the old name until it is re-registered. Mitigation: lock URLs list two providers (GitHub Releases plus an object-store mirror on a domain we control); signatures make squatting a denial, not a forgery.
* *A message that reads differently on a terminal.* A lock, a capsule's `capsule.json` or a host path can hold escape sequences, carriage returns or bidirectional controls. Printed as they are, these rewrite or reorder what the user reads, including a fix command the user will paste. Mitigated (DX rule C9): text and terminal messages, and every note, show each such character in a value as `?`; `--json` writes it as `\uXXXX`. Tested: a golden sample rendered by both launchers, and `tests/install.rs`. Residual: `fetch.log`, and output that a program reads back (`env` lines, a printed store path), keep values exactly.
* *First-launcher trust is TOFU over TLS.* Mitigation: publish the root key fingerprint in at least two independent places (README, release notes, DNS TXT) and ship the launcher through independently reviewed manifests (Homebrew, winget, Nix) whose own hashes pin it; `self-update` verifies new launchers with the embedded key. Residual: `curl | sh` users.

==== Tampering
* *Flipped or truncated bytes, substituted capsule.* Mitigated: sha256 of the archive and `sha256sums.txt` of the tree before anything runs; partial downloads are deleted on mismatch (`E-HASH-MISMATCH`). Drilled.
* *Rollback / freeze / mix-and-match of the channel.* Mitigated: monotonic `channel_version` recorded in the lock (`E-CHANNEL-ROLLBACK`), `expires` (`E-CHANNEL-EXPIRED`, explicit override only), one manifest covering all targets. Residual: a fresh install with no prior lock accepts any manifest inside its expiry window; a rotatable key list signed by an offline root (two-tier TUF-lite) is the planned Phase 2 addition.
* *Code injection through the environment.* Idris 2 treats `IDRIS2_DATA`, `IDRIS2_LIBS`, `IDRIS2_PACKAGE_PATH`, `IDRIS2_INC_SRC` and `IDRIS2_PATH` as search paths and splices `support.ss` into every compiled program; `LD_LIBRARY_PATH`/`DYLD_LIBRARY_PATH` select `libidris2_support`. Mitigation (ADR 0005): the launcher *sets* every one of these, inheriting none unless `--inherit-env` is passed, and never places user-writable directories ahead of the capsule.
* *Overlays as an injection vector.* Overlays are capsules: content-addressed, listed by hash in the signed manifest, verified like a base capsule. No post-install scripts, ever.
* *Archive extraction.* Rules (PEP 706 "data" filter equivalent): reject absolute names, `..` components, links resolving outside the staging tree, hardlinks (materialise as copies), devices/fifos; strip setuid/setgid/sticky and group/other write; `lstat` parents so nothing writes through a link; the factory rejects case-fold duplicate names (macOS). Drilled: `..` member and escaping symlink. The Phase 1 Go extractor must use a containment check, not `filepath.Join(dst, Clean(name))` (the audit's skeleton showed that escapes).
* *Store races.* Per-digest `flock`; staging → rename; `.complete` written last; directories without the marker are garbage. Drilled: four concurrent installs, lock contention, write-limit failure.

==== Repudiation
* Every published capsule carries SLSA provenance and a Sigstore attestation; *the factory verifies the build attestation before the channel is signed* (attestation-gated signing), so the channel signature implies a verified build. Immutable GitHub releases prevent silent re-upload. The launcher does not verify attestations (offline, stdlib); humans and CI do with `gh attestation verify`.

==== Information Disclosure
* GitHub and Cloudflare access logs see IP, user agent and the capsule name (OS/arch/version). Mitigation: fetches only on explicit `pin`/`update`/`install`, generic User-Agent, no install IDs, no background checks, `IDRIS2X_OFFLINE`, self-hosted channels. Documented in the privacy policy.

==== Denial of Service
* *Mirror outage / bandwidth throttling (GitHub AUP §9).* Mitigated: `urls[]` per capsule across two providers, resume via `Range` (always re-requesting the stable github.com URL, since the redirect target is a five-minute signed URL), hedged fetch in Phase 2.
* *Abandonment.* Mitigated: execution never needs the manifest; immutable releases survive archiving; sunset manifest with long `expires`; archival copies (Internet Archive item; IPFS pin) in Phase 2.
* *Disk full / interrupted install.* Typed failure, store unchanged. Drilled.

==== Elevation of Privilege
* The launcher writes only under its cache, its temp dir and the project directory; never needs `sudo`; strips special permission bits on extraction; refuses to run anything before verification. Chez and Idris 2 run with the user's privileges only.

=== Residual Risks and Decisions Deferred

* Single signing key until Phase 2 (rotation list signed by offline root).
* Intel macOS runners are sunsetting (~2027); `x86_64-apple-darwin` may need cross-build (`make bootquick XM=ta6osx`) or demotion.
* Compiled user programs embed the store path (`#!<store>/bin/scheme --program`) and break if the store path contains spaces or the capsule is garbage-collected; `doctor` warns, docs recommend `--cg refc` for long-lived artifacts.
* Export-control notification for distributing TLS-containing binaries is a policy question for the estate (not legal advice).
