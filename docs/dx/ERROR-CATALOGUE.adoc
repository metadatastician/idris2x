*Status.* The Rust launcher does not exist. Everything described as running here runs in the bash prototype
(`scripts/proto/idris2x.sh`). All 17 IDs (44 cases) have wording in two styles, rendered and regression-tested.
The owner ruled on 2026-11-16 that both styles ship and each user chooses.

== How to read this page

* The exact rendered text for every case of every ID, in every form (interactive terminal, plain, `--json`) and both
  styles, is in link:ERROR-CATALOGUE-RENDERED.adoc[the generated page]. It is generated from `src/errors/errors.toml`

== Two styles, the user's choice

Two styles are rendered from the same data, and `IDRIS2X_STYLE=a` or `IDRIS2X_STYLE=b` selects one. Style A is conversational, after Elm. Style B is one labelled field per
line, after rustc and cargo. One failure, both styles, plain form:

.Style A
[source,text]
----
idris2x: E-HASH-MISMATCH (exit 11)

The capsule I downloaded is not the one idris2x.lock pins.

    expected  sha256:0d7a4c1e9b52f6a83c07d1e45b9a2f6c8e13d7b0a5942c6f1e8d3b7a094c5e21
    got       sha256:3f1c88a2d4e6071b95c3fa2e6d8097b4c1a5e3f7029b6d4c8a1e5f3b7d902c64
    size      17706495 bytes (the lock says 35412990)
    from      https://mirror.example.org/idris2-0.8.0-x86_64-unknown-linux-gnu-chez10.4.1.tar.gz

Nothing was installed. The bad download was deleted and the store is unchanged.

A mirror served a damaged, truncated or stale file. It can also mean tampering,
which is what this check exists to catch.

Try the download again:

    idris2x install --locked

If it fails again with the same got digest, the mirror is serving a bad file:
report it with the runbook below.

More: idris2x explain E-HASH-MISMATCH
https://github.com/metadatastician/idris2x/blob/main/docs/runbooks/E-HASH-MISMATCH.adoc
----

=== Switching, and the default

[cols="1,3",options="header"]
|===
| How | Status
| `IDRIS2X_STYLE=a` or `b` in the environment | Runs in the prototype; the whole chaos suite passes under each.
| `--style a` or `--style b` on the command line | Planned.
| `style = "a"` in the user's own configuration file, so a person sets it once | Planned. It must be a per-user file,
  never `idris2x.toml`: a project should not choose how its contributors read errors.
| `--json` | Unaffected by style: one object, the same for both.
|===

The default is style B. That is a design call made here, not an owner ruling, and it departs from what may be the
more elegant arm: style A when a person is at a terminal and style B everywhere else. B was kept as the default because
it is the same text in every setting, so a message pasted from a terminal matches the one in a CI log. The automatic
arm costs one line in the renderer and can be switched on later.

Cost of shipping both, stated plainly: every case keeps two headlines (`summary` and `story`), and both are tested.
That is 44 extra sentences to keep true.

=== Still worth measuring

Shipping both removes the need to choose before building. It does not show which default serves people best.
The measurement proposed earlier still applies and nothing in it has been run with people: show both styles to
newcomers, CI maintainers and experienced Idris 2 users; ask what happened, whether anything on disk is damaged,
and what to type next; and read each style through a screen reader once. Asking Idris 2 users is outward-facing,
so it waits for the owner (see link:ADOPTION.adoc[adoption]).

== The schema change (proposed in this branch, not silently)

`src/errors/errors.toml` moves from schema 1 to schema 2. Exit codes and IDs are untouched. Generators that read
`id`, `exit`, `meaning` and `fix` keep working: `gen-runbooks.sh --check` and `gen-issue-forms.sh --check` pass.

[source,diff]
----
-schema = 1
+schema = 2

 [[error]]
 id = "E-HASH-MISMATCH"
+title = "capsule bytes do not match the lock"       # constant per type; --json `title`
 exit = 11
 meaning = "downloaded bytes or unpacked tree do not match the pinned digest"
-fix = "idris2x gc && idris2x install --locked"
+fix = "idris2x install --locked"

+[[case]]                                 # one SHAPE the type takes at a call site
+error = "E-HASH-MISMATCH"
+case = "download"
+summary = "downloaded capsule does not match {lock}"            # style B headline
+story = "The capsule I downloaded is not the one {lock} pins."  # style A headline
+facts = "expected=want got=got size=bytes from=source"          # label=context-name, in order
+state = "Nothing was installed. The bad download was deleted and the store is unchanged."
+why = "A mirror served a damaged, truncated or stale file. ..."
+fix_lead = "Try the download again:"                            # style A only
+fix_cmd = "idris2x install --locked"
+fix_note = "If it fails again with the same got digest, ..."
+auto = "safe"                                                   # safe | placeholder | none
----

Why two tables. An error *type* (`[[error]]`) is the stable contract: ID, exit code, title. A *case* (`[[case]]`) is
one situation in which that type occurs. `E-PIN-NOT-FOUND` has three: no lock file, a lock without this platform, and
a version the channel lacks. Their causes and fixes differ, so one sentence cannot serve all three. A call site now
reads `fail E-PIN-NOT-FOUND no-target lock=… target=…` and contains no prose.

What the change costs:

* The file stays inside the strict TOML subset `scripts/lib/toml2json.sh` accepts: strings and integers only, which
  is why `facts` is one string. The launcher's own reader has the same limits.
* Both styles ship, so `summary`, `story` and `fix_lead` all stay.
* A new `[[advice]]` table holds notes that are not errors. Each entry has `review_by`, `retire_when` and `basis`,
  and `scripts/check-advice-review.sh` fails once a review date has passed (see the DX principles, rule H5).
* The `[[case]]` blocks will conflict textually with any edit the main thread makes to the same file. The conflict is
  one-off and mechanical.

`--json` output also changes shape, from `{error, message, fix, runbook}` to the object shown on the generated page.
Nothing consumed the old shape. One call to the old `die` function remains in the prototype: the last resort when
the message data itself cannot be read.

== The first five IDs

Each row gives the case, the fact the user needs, the fix, and what was wrong before.
Rendered text: link:ERROR-CATALOGUE-RENDERED.adoc[generated page].

[cols="2,2,3,3,3",options="header"]
|===
| ID and case | Cause | The fact the user needs | Single best fix | Before, and what was wrong

| `E-PIN-NOT-FOUND` `no-lock`
| No `idris2x.lock` in the current directory
| Which directory was searched
| `idris2x pin <version>` (placeholder)
| `no idris2x.lock in /path`. No reason given; did not say the lock is read from the current directory only.

| `E-PIN-NOT-FOUND` `no-target`
| The lock has no capsule for this platform
| This platform's target, and the targets the lock covers
| `idris2x pin 0.8.0` with the lock's own version filled in (safe)
| Fix said `idris2x pin <version> on a supported target, or request the target`: two actions and a placeholder
  where the version was already known.

| `E-PIN-NOT-FOUND` `no-version`
| The channel offers no such version
| The versions it does offer
| `idris2x pin <version>` (placeholder)
| Listed versions as `idris2@0.8.0`, a form the user cannot type back.

| `E-HASH-MISMATCH` `download`
| Downloaded bytes differ from the pinned digest
| Both digests, the size against the pinned size, and which mirror served it
| `idris2x install --locked` (safe)
| Fix began with `idris2x gc`, which is not needed: the bad download is already deleted. The mirror was not named.
  Truncation was not distinguishable from corruption.

| `E-HASH-MISMATCH` `bundle`
| A bundle passed to `--from` is not the pinned capsule
| Both digests and the bundle path
| `idris2x fetch -o capsule.tar.gz` on a connected machine (none)
| Same text as a download failure, with a fix (`install --locked`) that cannot work offline.

| `E-HASH-MISMATCH` `store-modified`
| An installed capsule fails its own checksums
| The store entry's path
| `rm -rf <entry> && idris2x install --locked`, the path quoted when it needs it (none)
| Fix was `idris2x gc --purge sha256:…`. *That flag does not exist.* `sha256sum` output also leaked to the terminal.
  The new fix is tested end to end: chaos runs the printed command and then `verify` passes.

| `E-SIG-INVALID` `bad-signature`
| Manifest bytes do not match the signature
| The manifest URL and the trusted key id
| Repeat the same `pin` once (none)
| `investigate the mirror; do not override`: no next step, and no statement that pinned work is unaffected.

| `E-SIG-INVALID` `wrong-key`
| Manifest signed by a key other than the trusted one
| Both key ids and the URL
| No command. Check the URL; if right, update idris2x.
| Did not show either key id, so two reports could not be compared.

| `E-SIG-INVALID` `malformed`
| Key or signature file is not signify-format Ed25519
| Which file, and what is wrong with it
| No command. Open the file; fix the proxy if it is HTML.
| Four call sites with four hand-written sentences and no fix line.

| `E-OFFLINE` `capsule-missing`
| Offline mode is on and the capsule is not in the store
| The digest, the store path, and that offline mode is the reason
| `idris2x fetch -o capsule.tar.gz` on a connected machine (none)
| One line that put two commands for two machines in a single fix.

| `E-OFFLINE` `no-manifest`
| Offline `pin` with no cached manifest
| The cache path
| `IDRIS2X_OFFLINE=0 idris2x pin 0.8.0` (none)
| `run once online`. Did not say that running an existing pin never needs the manifest.

| `E-LOCK-TIMEOUT` `held`
| Another process holds this capsule's install lock
| The lock file and, when it can be seen running, the holder's process id
| `IDRIS2X_LOCK_TIMEOUT=1800 idris2x install --locked` (safe)
| Fix said `if no idris2x is running: rm <lock file>`. *That advice was unsafe*: `flock` locks vanish with their
  holder, so a held lock always has a live holder, and deleting the file lets two installs write at once.
|===

== The other twelve IDs

These now have wording in both styles, written from the analysis in this table. "Before" is the text the prototype
printed at commit `e1d7779`; the last column says what was wrong with it. Two IDs are exceptions: `E-PIN-DRIFT` has
wording and a golden rendering but still no code path, because the prototype does not read `idris2x.toml`.
`E-PLATFORM-UNSUPPORTED` is wired but was not drilled, since the test machine is a supported platform.

[cols="2,2,3,3,3",options="header"]
|===
| ID (exit) | Cases to write | The fact the user needs | Single best fix | Before, and what must change

| `E-USAGE` (2)
| unknown-command, unknown-flag, missing-argument, no-such-file
| The token that was not understood, and the nearest valid one
| The corrected command when one candidate is close; else `idris2x --help`
| Prints the whole usage string for every mistake. cargo and uv both print one `similar` suggestion instead.

| `E-PLATFORM-UNSUPPORTED` (13)

| `E-NETWORK` (14)
| all-mirrors-failed, manifest-unreachable
| Each mirror tried with its own outcome (DNS, TLS, HTTP status, timeout), as a chain from request to cause
| `idris2x install --locked` (safe to retry)
| `all 2 mirror(s) failed`, with causes left in a log file. Show them (W7).

| `E-CHANNEL-SCHEMA` (18)

| `E-PIN-DRIFT` (19)
| toml-vs-lock
| Both versions and both file names
| `idris2x pin <version from idris2x.toml>` with the version filled in (safe)
| No call site in the prototype. Model on bun: name the first differing item and the exact repair.

| `E-CAPSULE-INVALID` (21)
| unsafe-path, no-metadata, tree-mismatch
| The digest, and the first offending member name
| No command. Report the digest; nothing was unpacked.
| `report this capsule digest upstream` is ambiguous: "upstream" must mean the idris2x channel, never Idris 2.

| `E-CHANNEL-ROLLBACK` (22)
| version-went-back
| The version the lock saw, the version offered, and the URL
| No command. Retry later; if it persists, report the mirror.

| `E-CHANNEL-EXPIRED` (23)
| expired
| The expiry time, the time now, and how long ago it expired
| Repeat `idris2x pin <version>` (safe); then the stated override `IDRIS2X_ALLOW_EXPIRED=1`, with what it gives up

| `E-STORE-IO` (24)
| cannot-create, no-space, rename-failed
| The path, the operating system's own error text, and free space when the cause is space
| For no-space: `idris2x gc`. For permissions: no command; show owner and mode.
| Four sites, each guessing (`disk full or corrupt gzip`). Report the OS error instead of a guess (W6).

| `E-INTERNAL` (70)
| bug, missing-tool
| The launcher version and what to attach
| `idris2x doctor --json > doctor.json`, then the issue form
| `missing tool: curl` is a prototype-only case. The Rust launcher has no external tools.

== Defects found while doing this work

Found by reading and running the prototype, not hypothetical. Eight are fixed in this branch and two are open.

. *Fixed.* The runbook link pointed to `blob/main/runbooks/`, which does not exist. It is `blob/main/docs/runbooks/`.
. *Fixed.* The `E-LOCK-TIMEOUT` fix advised deleting a held lock file.
. *Fixed.* The `store-modified` fix named `idris2x gc --purge`, a flag that does not exist.
. *Fixed.* A write failure during download exited 14 (`E-NETWORK`). It now exits 24 (`E-STORE-IO`). Tested with a
  file-size limit, which stands in for a full disk; a truly full disk was not tested.
. *Fixed.* `E-NETWORK` said only that all mirrors failed. It now lists each address with its own reason.
. *Fixed.* `E-GLIBC-FLOOR` had no code path. It is now checked before any download.
. *Fixed.* Three `E-PROBE-CODEGEN` sites printed by hand. They now go through the same data as every other error.
. *Fixed.* `tar` printed its own warning in front of `E-CAPSULE-INVALID`. The exact-text drill caught it.
. *Open.* `E-PIN-DRIFT` has an ID, a runbook and wording but no code path in the prototype.
. *Open.* `idris2x gc` deletes capsules without the warning ADR 0005 requires about compiled programs.

One defect was introduced and removed during this work, and is recorded because of how it was found. An edit split a
line in the archive safety check, which silently disabled the test for links that leave the capsule tree. The chaos
suite still passed. A line-by-line comparison of the journeys page with a fresh run exposed it. Two drills were
added (a successful install prints nothing but the store path; a capsule with an escaping link is refused), and
they fail on a copy with the fault put back.

== Added after Phase 0

`E-OUTPUT` (25), case `write-failed`, was added on 2026-11-26 while building the Rust launcher. Writing to standard
output can fail: the disk or file it goes to is full, or the program reading it stopped early. Before this ID, the Rust
launcher panicked and reported `E-INTERNAL`, which tells the user the fault is in idris2x. The prototype printed a
`jq` error and exited 2, the code of `E-USAGE`. A test in `tests/cli.rs` writes to `/dev/full` on Linux.

A closed standard output (`>&-`) is not detected. The Rust runtime reopens it as `/dev/null` before the launcher
starts, so the output is thrown away, as it would be with `>/dev/null`.
