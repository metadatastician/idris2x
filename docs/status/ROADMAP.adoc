Phase 0 complete (2026-11-16): design pinned in ADRs 0004–0011 and tested on real builds (see PHASE0-REPORT.adoc).
Phase 1 in progress (2026-11-27): the Rust launcher was built in four milestones, and all four are merged
(milestone 4, pin, channel trust and the exec map, in #9), built and tested with `cargo test`. The chaos suite now
drives the Rust launcher too (128 of 128 on each launcher, both styles, 2026-11-27, run by hand through
`scripts/proto/chaos-gate.sh`). The CI job `.github/workflows/chaos.yml` runs the same four runs on GitHub. Its
first run failed one check, because the suite passed the job's `IDRIS2_PREFIX` on to its drills. With that fixed,
it passed on 2026-11-27 (run 45932797650 at 5f53e0c: four runs of 128 passed, 0 failed, in 16 minutes). It is not
yet a required check. It runs on every pull request, and `.github/rulesets/Chaos-Gate.json` makes it one once the
owner applies that ruleset; until then a red run does not block a merge.

run passed on 2026-11-27 (run 45988074983). It is not a required check.

=== Phase 2 — Trust layer
* [ ] Mirrors, hedged fetch, nightly canaries, churn drill, status page
* [ ] SLSA provenance, SBOM, immutable releases, two-tier keys
* [ ] Overlays, air-gap bundles, runbooks with triage notes
* [ ] Points from the Phase 1 design review, moved here by the owner on 2026-11-27, each with the reason it waits:
** `E-NETWORK` quotes the transport library's error words labelled as lock text (`src/store.rs`, `download`). They
   come from the host, not the lock, so the label is wrong (ADR 0012); no slot misuses them today.
** Temporary files are named by process id: `pin` writes `idris2x.<pid>.tmp` beside the lock and `doctor` writes
   `.doctor-<pid>` in the store. A crash leaves one behind, and a later `pin` that gets the same id fails on it, loudly.
   A held lock names the last pid recorded there, which may have ended; the message now says so.
** `gc` keeps every name it did not write and says nothing about it (I3). It should list them.
** The refusal of an https mirror that redirects to plain http rests on the transport library's `https_only` and has
   no test of its own.
** The prototype lacks seven checks the Rust `pin` has (`seen-version-unknown`, `pin-held`, `channel-changed`,
   `other-version`, `needs-newer-launcher`, `malformed-manifest`, `bad-toml`), so the chaos suite cannot compare the
   two launchers on them.
** `E-PIN-DRIFT/channel-changed` was the agent's design call, not the owner's: when `idris2x.toml` changes channel
   while `pin` waits its turn, `pin` stops with a typed error instead of starting again on the new channel.
** `pin` keeps the verified manifest before it writes the lock, so a failed lock write leaves a checked copy that an
   offline `pin` checks again. Also the agent's call, for the owner to confirm or reverse.
** Prototype parity for the two Phase 1 holes: the prototype's `exec` takes no capsule lock, and it accepts a cache
   path with a control or hidden character. The chaos suite does not test either.
** `exec` waits for its shared capsule lock with no time limit, so it waits as long as an install or `gc` holds the
   capsule.
