= Proof Status — IDRIS2X

This is the repository's proof-status file in the sense of
`standards/3-practice/PROOF-POLICY.adoc` §8.5: one row per claim, with its status
token, its Proof Witness Grade (PWG) and its recheck legs. The estate census
(hyperpolymath/mathesis) reads this file. A row says only what a receipt or a
gate supports.

The table below lists this repository's claims, one row each. Do not summarise it with a percentage or an "overall" figure:
§8.4 forbids percentages, averages and single scores for proofs.

== Vocabulary

* *Status token* (§5): `proven`, `proven-with-postulates`, `tested-only`,
  `argued`, `open`.
* *PWG* (§8), always written with its prefix, never as a bare "Grade":
** `PWG-3`: the Agda proof is `proven` or `proven-with-postulates` under the
   canonical §2.1 invocation, `agda --safe --without-K --cubical-compatible`,
   and no recheck leg counts yet;
** `PWG-2i`: one recheck leg also counts (Rocq or Lean);
** `PWG-2ii`: both legs count;
** `PWG-1`: `PWG-2ii`, plus every counted witness (Agda, Rocq and Lean) has a
   current receipt from a headless, isolated, pinned checker run on the exact
   source commit;
** `ungraded`: a theory row below `PWG-3`, or any row with no receipt yet, an
   `open` row included, whether it is a theory theorem or an engineering
   obligation;
** `n/a`: not on the ladder once it has a result: a test, a refusal fixture, an
   assumption, or a discharged engineering proof in Idris2, SPARK, Creusot or
   Verus. §8.1 puts these off the ladder. An `open` engineering obligation is not `n/a`: an `open` engineering
   obligation stays `ungraded` until it has a receipt.
* *Recheck legs* (§2): `transported`, `re-proved`, `waived` or `unavailable`,
  each with its §2.2 correspondence state, for example `BRIDGE-PENDING` or
  `RECONCILED`. A leg counts towards a grade only when it is `RECONCILED`.

A grade is derived from receipts, not asserted (§8.4). Name the receipt in the
table, and a claim that has none stays `ungraded`. `PWG-3` is not a discharge:
a theorem at `PWG-3` still owes both legs.

The template's own sample proofs under `verification/proofs/` are boilerplate.
They are never rows here: replace them with this repository's proofs, or delete
them.

|===
| Boundary | What is assumed, and why | Claims

| Ingress labelling
| The code that reads the channel, the lock and the host calls the matching entry point (`fromChannel`, `fromLock`, `fromHost`). The model cannot see that code: a `String` read from the channel and handed to `fromHost` would be mislabelled. The model proves non-flow *after* labelling, and rejects relabelling of rendered output (negative case 8). The Rust launcher keeps it to four functions in `src/msg.rs`, `embedded`, `host`, `lock` and `channel`, so it can be reviewed by reading their call sites; `scripts/check-msg-negatives.sh` keeps every call of `channel` in `src/pin.rs`. `embedded` takes only `&'static str`, which stops a string read at run time by accident but not on purpose: `Box::leak` would get one past it, and is the same kind of mislabelling.
| DX-PROV-1, DX-PROV-2

| Format checks
| `checkDigest` and `checkVersion` are trusted by inspection, not proved, to admit no shell syntax: a digest is 64 characters from `0-9a-f`, a version is two to four runs of one to 19 decimal digits separated by dots, so every run fits in 64 bits and two versions always compare. The prototype applies the same checks in `scripts/proto/idris2x.sh` `resolve`, and the Rust launcher in `src/msg.rs` `check_digest` and `check_version`.
| DX-PROV-1, DX-PROV-2

| `tar` headers (`ASSUMED`, third-party)
| The `tar` crate returns each member's name, link name, kind and mode as the archive holds them. The launcher's own checks act on those values; the crate's parsing is not checked.
| STORE-1

| `ring` SHA-256 (`ASSUMED`, third-party)
| `ring`'s SHA-256 is correct, so equal digests mean equal bytes up to the hash's collision resistance.
| STORE-2

| `ring` Ed25519 (`ASSUMED`, third-party)
| `ring` accepts an Ed25519 signature only if it was made with the private half of the given public key (RFC 8032), up to the scheme's own security.
| TRUST-1

| `serde_json` parsing (`ASSUMED`, third-party)
| `serde_json` reads a verified manifest's fields as the JSON text holds them. The launcher checks the format of every value it copies into a lock; the parsing itself is not checked.
| TRUST-1

| `std` Euclidean division (`ASSUMED`, third-party)
| `i64::div_euclid` and `i64::rem_euclid` return the Euclidean quotient and remainder, as the standard library documents, for a non-zero divisor that is not -1 with `i64::MIN`. Creusot does not check `std`; the `extern_spec!` block in `verification/proofs/creusot/src/lib.rs` states this contract, and `src/civil.rs` calls them only with the positive constants 400 and 146097.
| DATE-1

| Rename is atomic
| On one file system, a rename replaces its target whole or not at all (POSIX), so a reader sees the old lock or the new one.
| TRUST-1

| Staging tree is private
| Nothing else writes under the staging directory while an install holds the per-digest lock. Another process running as the same user could break this; the launcher does not defend against that.
| STORE-1, STORE-2

| Advisory file locks
| `File::try_lock` (flock on Linux) excludes every other idris2x process that locks the same file. Locks are advisory: a program that ignores them, or a file system that does not support them, breaks this. `exec` takes no lock, so `gc` cannot see a capsule that is running.
| GC-1
