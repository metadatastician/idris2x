= Prior art: does anything already do this, and what to borrow
:toc: macro

From the Phase 0 prior-art audit (primary sources: upstream repos, package indexes, download manifests; 27 findings).

== Idris 2 distribution today

[cols="2,4",options="header"]
|===
| Route | What it actually does
| `pack` (stefan-hoeck/idris2-pack) | Builds the compiler *from source* per collection with a bring-your-own system Chez (or Racket); collections are TOML files pinning git commits (unsigned, no Chez version); nightlies rebuilt ~1 am UTC; no Windows story
| Homebrew `idris2` | Prebuilt bottle depending on Homebrew `chezscheme` 10.4.1; bakes the Homebrew Chez path in — fine for brew users, not relocatable
| Distros | Debian/Ubuntu package Chez (9.5.4 … 10.4.1 depending on release) but not Idris 2; Fedora packages both; Arch only via AUR; nixpkgs has both (Chez 10.4.1) and wraps idris2 with `CHEZ`
| asdf / mise | No Idris 2 plugin exists; the mise `chezscheme` entry is a vfox plugin that compiles from source
| GitHub Actions | No `setup-idris2`; upstream publishes no nightly or release binaries (CI artifacts only)
| Docker | Active images: `mattpolzin2/idris-docker` (nightly), `ghcr.io/joshuanianji/idris-2-docker` (multi-arch, v0.6–v0.8), `ghcr.io/stefan-hoeck/idris2-pack`
| Upstream | PR #3857 (installers, open, unreviewed) confirms the direction: installed Idris 2 always uses `IDRIS2_PREFIX`, still needs system Chez, and recompiles if the Chez version differs — i.e. the Chez+Idris2 pair must be pinned together, which is the capsule
|===

Verdict: nothing provides hermetic, immutable, offline-cacheable Idris 2 + Chez pairs. The gap is real.

== Prebuilt Chez anywhere?

Only Homebrew bottles (7 platforms, `cellar :any_skip_relocation`, fetched via ghcr with an anonymous token) are a viable Tier-2/mirror source for *Chez only*. conda-forge has no package; Racket's bundled Chez is not standalone; cisco ships Windows installers only.

== Conventions to borrow

[cols="1,3",options="header"]
|===
| Project | Borrow
| Zig | `download/index.json` with sha256 + size per tarball; per-tarball minisign; community-mirror protocol (mirror list, origin last); note the index itself is unsigned
| uv / python-build-standalone | sha256 table baked into the launcher release; `SHA256SUMS` + GitHub release attestations on the artifact side
| rustup | TOML channel manifests with per-target url/hash; dated archives as rollback; lesson: signatures exist but are not enforced — we enforce
| ghcup | GPG-signed metadata with sha256 per download and distro requirement lists — closest existing model to our signed channel
| mise (aqua backend) | checksum + cosign + SLSA + minisign + GitHub-attestation verification, verified lockfiles, baked registry snapshot, dated deprecation warnings
| Bazel `http_archive` / Nix fixed-output derivations | `urls[]` tried in order, sha256 mandatory, mirrors first
| elan / juliaup | *anti-patterns*: elan verifies nothing (TLS only), juliaup's version DB has no hashes; both rely on exe-relative layouts for relocation (as Chez 10 does)
|===

== Options scored (elegance / dependability, 1–5)

* Build on pack as the pin layer — 3 / 2: community standard, but compiles from source on every machine with BYO Chez.
* Wrap the mise/aqua registry (publish capsules as an aqua/github recipe) — 4 / 3: inherits mise's verification and lockfiles and solves first-launcher trust for mise users (independently governed hash), but the capsules must still be built and hosted by us. Worth doing *in addition* for the estate, which already standardises on mise.
* Contribute a `setup-idris2` action on upstream nightlies — 3 / 2: there are no upstream nightlies.
* Own capsule + tiny launcher (the plan) — 4 / 4: the only route to hermetic, immutable, offline pairs. Chez 10's executable-relative boot path makes half of it free.
